# 指针缩放 —— 技术方案

> **效果**：平时指针保持较大；**按下**鼠标时按缓动曲线动画缩小；**松开**后按曲线动画恢复。
> 动画全程指针是**真正的系统光标**，可以自由移动、正常点击，交互零影响。
> 形态：带图形界面的小工具（也可无窗口后台运行），可配置大小、时长、缓动曲线。

状态：**核心链路与图形界面均已在本机实测通过**，可运行成品已落地（见第九节）。

---

## 一、效果定义

| 状态 | 指针大小 | 说明 |
|---|---|---|
| 平时（不点击） | `idle_size`，默认 48px | 常驻的「大」状态 |
| 按下鼠标 | 从 `idle_size` 按 `press_curve` 动画缩小到 `click_size`，默认 25px | 时长 `press_duration_ms`，默认 80ms |
| 松开鼠标 | 从 `click_size` 按 `release_curve` 动画恢复到 `idle_size` | 时长 `release_duration_ms`，默认 83ms |
| 退出程序 | 恢复 `original_size` | 用户原本的系统设置，从注册表读取 |

默认曲线是「按下 `ease_in_quad` + 松开 `ease_out_quad`」，两端都是先慢后快 / 先快后慢的
二次缓动，整体是「按下去迅速收一下、松开再迅速弹回来」的干脆手感。想要过冲的
活泼效果，把 `release_curve` 换成 `ease_out_back` / `ease_out_elastic`，
再用 `curve_strength` 调幅度。

两个大小、两个时长、两条曲线全部可配。

## 二、关键前提：为什么这个效果反而更容易做

需求里有一条硬约束 ——「要能交互，指针能同时运动」。这一条直接决定了技术路线。

自绘覆盖窗口的方案（隐藏系统光标 + 自己画一个放大的指针跟着鼠标跑）在这里会直接失败：动画期间指针是被「画」出来的，点击要转发、移动会跟手延迟，本质上已经不是系统光标了。

而**系统原生缩放**路线下，指针**从头到尾都是那个真正的系统光标**，我们只是在改它的尺寸属性。所以：

- 指针可以自由移动 —— 系统自己负责绘制和跟随，零延迟。
- 点击、拖拽、悬停、滚轮 —— 全部原样工作，因为我们根本没碰输入链路。
- 热区自动正确 —— 系统按比例处理，不需要我们换算。
- 动画不会阻塞任何操作 —— 动画在独立线程里跑，与输入完全解耦。

## 三、核心 API（已在本机验证）

```c
SystemParametersInfoW(0x2029 /* SPI_SETCURSORBASESIZE */, 0,
                      (PVOID)(UINT_PTR)size_px,
                      flags);   /* 动画帧传 0，落定帧传 SPIF_SENDCHANGE */
```

一次调用，**整套系统光标**（箭头 / 文本 I 形 / 手型 / 各种调整大小箭头 / 忙碌圈）全部按像素等比放大或缩小。

- 取值范围 `1 – 256`，对应 Windows 设置页 1–15 档（32 / 48 / 64 / … / 256，每档 +16px）。
- `0x2029` 是**未公开文档**的 SPI 常量，公开 API 文档里查不到 `SPI_SETCURSORBASESIZE` 这个名字。

### 本机验证结果（实测）

```
[读取] CursorBaseSize = 48      ← 系统当前设置（第 2 档）
[读取] Accessibility\CursorSize = 2
[探测 1] flags=0               -> 返回 True  GetLastError=0   注册表未被修改
[探测 2] flags=SPIF_SENDCHANGE -> 返回 True  GetLastError=0   注册表未被修改
[探测 3] 连续 12 帧动画        -> 耗时 214ms（约 56fps），失败 0 帧
```

结论：SPI 被系统识别，**且不带 `SPIF_UPDATEINIFILE` 时完全不写注册表**，60fps 连续调用可行。方案成立。

### 三条铁律

1. **动画帧绝对不能带 `SPIF_UPDATEINIFILE`（0x01）**。否则每帧都写一次用户配置文件 —— 一秒 60 次，既伤盘又可能把动画中间值持久化。
2. **动画帧也不能带 `SPIF_SENDCHANGE`（0x02）**。它是向**所有顶层窗口**广播 `WM_SETTINGCHANGE` 的开关，详见下一节 —— 这是「动画期间指针会闪」的根因。
3. **注册表始终保存用户自己的设置，我们只读不写**。所以「原始大小」永远有一个可靠的真值来源，进程崩了也不会丢。

### 闪烁根因：逐帧广播 `WM_SETTINGCHANGE`

第一版把 `flags` 写死成 `SPIF_SENDCHANGE`，理由是「改完要通知系统」。结果动画一跑就闪。

链路是这样的：

```
动画第 N 帧   SystemParametersInfoW(0x2029, px, SPIF_SENDCHANGE)
              ├─ 内存里的光标基础尺寸 -> px          （生效）
              └─ 广播 WM_SETTINGCHANGE 给所有顶层窗口
                        ↓
              每个响应广播的程序重新读一遍系统光标设置
                        ↓
              读的是注册表 CursorBaseSize —— 而动画**从不写注册表**，
              那里还是「原始大小」48px
                        ↓
              这些程序把光标按 48px 重设回去   ← 一次「闪」
动画第 N+1 帧 再把尺寸改成 px'，它们再重设回 48px   ← 又一次「闪」
```

帧率越高闪得越密 —— 当初开发机上配的是 `fps = 144`，等于每秒 144 次这种拉扯，
所以现象特别明显。

**修复**：动画帧一律 `flags = 0`，只在动画落定那一帧广播一次。

```python
flags = SPIF_SENDCHANGE if notify else 0
```

为什么去掉广播不会让尺寸变化失效？实测两种调用的耗时几乎一样：

```
SPIF_SENDCHANGE   平均 0.68ms   中位 0.62ms   最差 2.55ms
flags = 0         平均 0.70ms   中位 0.53ms   最差 1.87ms
```

如果「改尺寸」这件事是靠广播触发的，`flags=0` 就该快到接近 0 —— 它没有。
说明**光标重绘发生在 SPI 调用内部**，广播只是通知，去掉它不影响生效。

保留 `[animation] broadcast = every_frame` 作为退路：万一在某些环境上发现
尺寸真的不生效，改回旧行为即可。

### 顺带修掉的：`snap()` 从未下发

`snap(size)` 走的是 `goto(size, 0, ...)`，而 `goto` 在「时长为 0」时只改了内存里的
`current` 就返回，**从没调用 `apply_size()`**。于是这些路径全是空操作：

- 启动时切到平时大小
- 「恢复原始大小」快捷键 / 界面上的恢复按钮
- 启用 / 停用开关
- 未按下时拖动大小滑块

指针会一直停在旧尺寸，直到下一次动画的第一帧才被顺手带过去 —— 表现为突然一跳。

修复后 `goto` 在 `_active` 为假时直接下发一次（带广播，因为这是一次性动作）。

## 四、动画实现

### 4.1 线程模型

无界面版（`pointer_zoom.py`）：主线程就是钩子线程。

```
主线程                    动画线程（daemon）                 钩子回调
  │                             │                              │
  ├─ GetMessage 消息循环 ◄──────┤                              │
  ├─ WM_HOTKEY 处理             ├─ 每帧：算缓动值              │
  └─ WH_MOUSE_LL 钩子 ──────────┼─ 调 SystemParametersInfo ◄────┘
                                │                        （只置一个标志位）
```

图形界面版（`pointer_gui.py`）：**tkinter 必须独占主线程**，所以钩子被挪到独立线程。
关键是界面**不做任何跨线程回调** —— tkinter 不是线程安全的，从钩子线程里调
`after()` 或直接改控件迟早会随机崩溃。界面统一用 `after(60, ...)` 轮询读状态，
虽然多了一点轮询开销，但换来了确定的稳定性。

```
主线程（tkinter）          钩子线程                     动画线程
  │                          │                            │
  ├─ mainloop 事件循环       ├─ SetWindowsHookEx          ├─ 每帧算缓动值
  ├─ after(60) 轮询读数  ◄───┤─ RegisterHotKey            ├─ 调 SystemParametersInfo
  │   （只读，不跨线程写）   ├─ GetMessage 消息循环        │
  └─ 滑块/按钮改配置 ────────┼─ WH_MOUSE_LL 钩子 ──────────┘
       （原子替换 cfg 字典） └─ WM_HOTKEY 处理
```

配置同步靠**整体替换 `app.cfg` 字典**：CPython 里 `d[k] = v` 和引用赋值都是原子的，
钩子线程读到的要么是旧字典要么是新字典，不会读到改了一半的状态。比加锁简单且够用。

界面改动即时生效：拖「平时大小」滑块且当前没按住鼠标时，直接 `anim.snap()` 把新尺寸
写进系统；其余参数在下一次按下/松开时自然生效。

### 4.1.1 界面外观层（v1.1 新增，`src/pz_ui.py`）

v1.1 把界面从「ttk 默认样式竖排」改成圆角卡片排版。核心动机：**ttk 的
LabelFrame / Scale / Checkbutton 是系统原生外观，配色和间距基本改不动**，这也是它
看起来老气的主因。所以滑块、开关、分段选择器、按钮、卡片都改成在 Canvas 上自己画。

三个实现要点：

1. **圆角矩形**。Canvas 没有原生圆角矩形，`round_rect()` 把四分之一圆弧按 `N` 个
   采样点展开，拼成多边形。填充和描边分开画，描边用 `capstyle=ROUND + joinstyle=ROUND`
   消掉接缝。
2. **颜色单一来源**。所有颜色收在 `pz_ui.THEMES` 的浅/深两张色板里。普通 tk 控件
   （Label / Frame / Entry）经 `ui.reg(w, bg=..., fg=...)` 登记**颜色键**；自绘控件
   实现 `retheme()`。换主题只做两件事：换 `pal` 字典、让各控件重画一次 ——
   不需要重建界面。
3. **卡片高度不自适应**。tkinter 的 Canvas 不会按内部内容撑高度，所以每张卡片
   构造时显式给 `width=CARD_W`，内容排完后调一次 `card.fit()` 量出 `inner` 的
   `reqheight` 再把 canvas 高度设上。

**这里踩过一个值得记住的坑**：Canvas 未映射时 `winfo_width()` 返回 **1**，而
`1 or 46` 得到 **1**（1 是真值）——「或」兜底在这里完全失效，结果开关被画到了
负坐标上、只剩一个孤立的小圆点。必须显式判 `if w <= 1: w = self.W`。
项目记忆里早就记过这条，写 `pz_ui.py` 时还是又踩了一次。

滑块旁的数值框从 `ttk.Spinbox` 换成了扁平 `tk.Entry`（`ValueEntry`）。注意**不能
直接给 Entry 绑 `tk.IntVar`** —— 非法输入会把控件搞乱，所以内部用独立 `StringVar`
双向同步：变量变 → 同步文本，回车/失焦 → 解析回写并回调。

改造**刻意保留了** `tests/test_gui.py` 依赖的全部接口（`var_*` / `_on_*` / `canvas`
/ `preview()` / `save_now()` …），所以 17 项界面测试一行没改、全过。

三条硬性要求：

- **钩子回调里只允许置一个标志位**。回调里做任何耗时操作都会给每一次鼠标事件加延迟；超过 `LowLevelHooksTimeout`（默认 300ms）系统会**静默摘掉你的钩子**。所以动画计算和 API 调用全部甩给独立线程。
- **动画线程按 `perf_counter` 计时**，不依赖 sleep 累加，避免长时间运行后漂移。
- **`timeBeginPeriod(1)`** 把系统定时器精度提到 1ms，否则 `sleep(1/60)` 实际会漂到 15–20ms。实测 12 帧 214ms ≈ 56fps。

### 4.2 缓动曲线

内置 17 条，写在 ini 里即可切换，`--curves` 可列出全部：

| 曲线 | 形态 | 建议用途 |
|---|---|---|
| `linear` | 匀速 | 对照用 |
| `ease_out_quad` / `cubic` / `quart` | 快出慢停，一档比一档更急 | **按下缩小** |
| `ease_out_expo` | 几乎瞬间到达，末尾极缓 | 想要「啪」一下的感觉 |
| `ease_in_out_cubic` | 两头慢中间快 | 柔和，不抢眼 |
| `ease_out_back` | 冲过头再弹回来 | **松开恢复**（默认） |
| `ease_in_out_back` | 两端都带回弹 | 更夸张 |
| `ease_out_elastic` | 橡皮筋抖动 | 最活泼 |
| `ease_out_bounce` | 落地弹跳 | 有趣 |

回弹类曲线会**过冲**（`ease_out_back` 会冲过目标尺寸再回来），所以尺寸必须钳制在 `[4, 256]`。

实测曲线数值（96px ↔ 32px，`ease_out_cubic` 按下 / `ease_out_back` 松开）：

```
按下  96.0 → 74.9 → 57.9 → 46.7 → 39.2 → 34.9 → 32.7 → 32.0px      136ms 到位
松开  32.0 → 52.8 → 70.5 → 83.9 → 93.1 → 98.7 → 101.5 → 102.4 → 101.9 → 96.0px
                                                      ↑ 过冲峰值     240ms 归位
```

### 4.3 中断处理

快速连点不能让指针跳变。做法是：动画的起点不是「上一次的目标」，而是**当前的实际尺寸**。每次状态切换时重新采样 `current` 作为起点，所以任何时刻打断都能平滑接上。

## 五、状态机

```
                      松开（release_curve）
              BIG（平时） ──────────────► SMALL（按住）
                96px      ◄──────────────   32px
                  ▲         按下（press_curve）
                  │
   Ctrl+Alt+R / 退出 / 停用 ──► ORIGINAL（用户原始设置 48px）
```

规则：

- **幂等**：目标尺寸和当前尺寸差值 < 0.75px 时不调 API，避免静止期空转重绘。
- **防重入**：已经按住时再收到按下事件直接忽略（拖拽、双击的第二次点击）。
- **可打断**：任何时刻切换状态都从当前尺寸重新起动画。
- **停用即归位**：快捷键停用时立刻恢复到 `original_size`，不留在放大状态。

## 六、安全兜底

指针尺寸是系统级状态，**进程如果在放大状态下死掉，指针就会一直很大**。四层防护：

1. **启动自愈** —— 程序启动第一件事就是把尺寸归位，顺手修掉上一次异常退出的残留。
2. **退出路径全覆盖** —— 正常退出、快捷键退出、`atexit`、`SIGINT`（Ctrl+C）、`KeyboardInterrupt`、未捕获异常，全部走同一个 `restore()`。
3. **只读注册表** —— 因为从不写入，注册表里永远是用户的真实设置，随时可以作为恢复目标。
4. **手动逃生** —— `reset.bat` 一键恢复；实在不行走 设置 → 辅助功能 → 鼠标指针和触控 → 把滑块拖回第 1 档。

另外做了**上限钳制**：如果用户本来就把指针设成了第 15 档（256px），程序会提示「无法再往上放」，而不是把尺寸撑到屏幕装不下。

## 七、技术栈选型

**本机实测环境**：无 gcc/g++/clang/cl、无 MSVC 与 Windows SDK、无 .NET SDK（只有 .NET 10 桌面运行时）、无 AutoHotkey；**有 Python 3.13.12**。

| 选项 | 交付物 | 优点 | 缺点 |
|---|---|---|---|
| **A. Python + ctypes**（已采用） | `.pyw` 直接跑，或 PyInstaller 打包 | 本机零安装即可运行；ctypes 直调 Win32；改代码立刻生效 | 需要 Python 环境；打包后约 10MB |
| B. AutoHotkey v2 | 单个 `.ahk`，可编译成 exe | 代码最短，改参数方便 | 需要先装 AHK；做复杂界面（曲线预览画布）很别扭 |
| C. C# WinForms / WPF | 单文件夹发布 | 界面最像原生 Windows 应用 | 需要 .NET SDK 才能编译 |
| D. C++ / Win32 | 单个绿色 exe，零依赖 | 体积最小、最干净 | 需要装 VS C++ 工作负载；写界面成本最高 |

先用 A 把效果调到你满意；效果定型后如果想要「双击 exe 就能用、不用装 Python」，再迁到 C 或 D 重写一遍 —— 核心逻辑只有 `SystemParametersInfo(0x2029, ...)` 这一行，迁移成本很低。

### 图形界面的一个环境坑

**同一台机器上装的多个 Python，tkinter 未必都有。** 开发机上就碰到过一个
精简发行版没有 tkinter、另一个官方安装版有（Tk 9.0.4，带 `vista` 主题）。
只按 `python` 这个名字去挑解释器，会在部分机器上直接崩在 `import tkinter`。

所以三个 `.bat` 都不是写死解释器，而是**按候选列表逐个试**：

| 脚本 | 判据 |
|---|---|
| `start.bat` | 试 `import tkinter`，第一个通过的就用来开界面 |
| `start_nogui.bat` | 只要 `pythonw.exe` 能跑就行，不要求 tkinter |
| `reset.bat` | 同上，只要 `python.exe` |

候选顺序是「常见安装位置 → `%LOCALAPPDATA%\Programs\Python` → `%ProgramFiles%` → `PATH`」，
全都不行才报错，并提示「安装 Python 时勾选 tcl/tk and IDLE」。

界面用 ttk + `vista` 主题，视觉上就是原生 Windows 控件，没有 tk 经典控件的年代感。

## 八、配置项

`pointer-zoom.ini`（与 `src/` 同级，改完重启程序生效）

```ini
[pointer]
idle_size = 48            ; 平时大小，像素；写 auto 表示沿用系统当前设置
click_size = 25           ; 按下缩小到的目标大小
trigger = left            ; 触发键：left / right / middle / both
enabled = true

[animation]
press_duration_ms = 80    ; 按下（缩小）动画时长，0 = 瞬间切换
release_duration_ms = 83  ; 松开（恢复）动画时长
press_curve = ease_in_quad
release_curve = ease_out_quad
curve_strength = 3.0      ; 回弹类曲线的强度，只对 back / elastic 有效
fps = 60                  ; 每一帧 = 系统重绘一次光标，闪/卡就降到 30
broadcast = settle        ; settle = 落定时广播一次（默认）；every_frame = 退路

[hotkeys]
toggle = ctrl+alt+p       ; 启用 / 停用
reset = ctrl+alt+r        ; 立刻恢复原始大小
quit = ctrl+alt+q         ; 退出
```

默认值的**唯一来源是 `pointer_zoom.INI_DEFAULTS`**：`pointer-zoom.ini.example`
由它生成，`load_config()` 在缺键时的兜底值也从它取，所以不会出现
「新生成的 ini」和「老 ini 缺键时的兜底」两套不一致的默认值。

**调参建议**

- 想更「弹」：`release_curve = ease_out_elastic`，`curve_strength = 2.5`。
- 想更克制：`release_curve = ease_out_quad`，`release_duration_ms = 160`。
- 按下去感觉慢：`press_duration_ms = 90`，`press_curve = ease_out_quart`。
- 如果动画期间指针还是闪，先把 `fps` 降到 60 或 30 —— 每一帧都是一次系统级
  光标重绘，帧率越高越容易看出闪。

### 诊断工具（`tools/`）

排查闪烁时写了几个探针，都保留了：

| 工具 | 作用 |
|---|---|
| `probe_cursor.py` | SPI 单次耗时、12 帧内的句柄重建次数 |
| `probe_flicker.py` | 子进程以 ~580kHz 采样 `GetCursorInfo`，统计「光标不可见」占比与句柄切换 |
| `probe_size.py` | 采样光标位图尺寸 / 热点轨迹，看尺寸是否单调 |

三个探针都指向同一个结论：**光标在系统层面观测不到**。
`GetCursorInfo()` 返回的句柄恒为 65539、位图恒为 32×32、`SM_CXCURSOR` 恒为 32，
无论把基础尺寸设成 32 还是 256 —— 也就是说，缩放发生在合成器层，
应用侧 API 看不到。所以「闪」不能靠采样证明，只能从广播机制上推断并消除。

> 采样踩过的两个坑，都写在探针注释里：
> ① `GetCursorInfo()` 会把 `cbSize` 清成 0，不每次重设的话第二次起就
> `ERROR_INVALID_PARAMETER(87)` 静默失败（30 万次循环里只有第 1 次成功）；
> ② 同进程的采样线程在 ctypes 密集循环里拿不到 GIL，一个样本都收不到，
> 必须换独立子进程。

## 十、已知限制

| 限制 | 说明 | 应对 |
|---|---|---|
| 独占全屏游戏 | 光标由游戏自己绘制，不认系统尺寸 | 加入排除列表（待实现）或停用工具 |
| UAC 安全桌面 | 钩子收不到事件 | 无影响，该场景本来也不需要 |
| 远程桌面 / 虚拟机 | 部分环境光标由宿主机绘制 | 接受为已知限制 |
| 某些程序缓存光标尺寸 | 需要鼠标移到该窗口上才刷新 | 一般移动一下就正常 |
| `0x2029` 未公开 | 未来 Windows 版本可能改动 | 已保留 `verify_spi.py` 随时复验 |
| 需要 Python 环境 | 目标机器没有 Python 就跑不起来 | 用 PyInstaller 打包，或迁到 C# / C++ |
| 图形界面需要 tkinter | 部分精简版 Python 没带 tkinter，装不上界面 | `start.bat` 会自动挑一个带 tkinter 的解释器；退一步用 `start_nogui.bat` |
| 界面窗口上的点击也会触发缩小 | 钩子是全局的，在窗口上调参数时指针也会缩 | 调参时取消勾选「启用」，或用 `Ctrl+Alt+P` 临时停用 |
